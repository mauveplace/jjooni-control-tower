# Control Tower 첫 화면 가치/사용성 재설계 — 형님 승인 전 검토안

**상태: PROPOSAL ONLY / USER APPROVAL REQUIRED / NO UI CHANGE / NO MERGE.**
**범위:** 인증된 Investment Control Tower의 `overview`(첫 화면) — Market Observatory의 `오늘` 탭과 별개.
**기준:** 공개 `main`의 `ct-human-v2.js`, `ct-human-v2.css`, `ct-reference-nav-history-v1.js`, `ct-performance-history-v1.js`, `index.html`, 과거 협업 검토 PR #488/#494 및 그래프 수정 #502/#503. 공개 소스와 합성 테스트 중심. **실제 인증 화면 미검증**.

## 1. 문제 정의 — 현재 화면이 투자자에게 답하는 질문이 흐리다

현재 V2는 `오늘의 투자 변화`라는 제목 아래 4계좌의 당일 투자손익/순입출금, 비교가능할 때 손익막대(아니면 현재 NAV 구성비), 성과 이동 링크 및 계좌/보유/성과/전략/품질 빠른 경로를 넣는다. 성과 그래프(참고 NAV)가 별도 카드로 Overview에 추가됐다.

- 총자산 NAV가 가장 먼저 읽히는 헤더인지, 오늘 투자손익이 검증되지 않았을 때 가장 중요한 실제 숫자가 무엇인지 불명확.
- 손익기여 그래프와 NAV 비중 그래프가 상태에 따라 같은 자리에서 교체되어, 자료 유형이 바뀐 것을 사용자가 놓치기 쉽다.
- `REFERENCE_ONLY` 순자산 추이를 넣었으나 인출입·환율 포함 증감을 성과로 오해할 위험. 3종 공식 성과는 검증된 원장이 없는 경우 표시 불가가 정답.
- 메뉴 2중 문제는 PR #494에서 개선했으나, 실제 인증된 모바일 화면·기기 회전과 누적 카드 밀도는 아직 실측 미확인.
- 확인 대기/자료 출처/경고 문구를 화면 상단에 그대로 쌓으면 유효 정보가 낮아지는 위험. 반대로 P0 오류는 어떤 경우에도 숨기면 안 됨.

## 2. 첫 화면에서 10초 안에 해결할 5개 질문

1. **지금 얼마인가?** 4계좌 동일 스냅샷 합산 NAV, 기준시각/포함계좌, 최신·지연·동기화 불일치
2. **얼마가 늘었고 왜인가?** 동일 기간 투자손익/순입출금 별도 표시, 비교불가 시 숫자 미노출, 확인된 계좌별 기여
3. **주의할 것이 있는가?** 실제 검증 가능한 1~3개 리스크/원천 오류만 우선순위 노출. 신규 리스크 계산/거래 판단은 이번 UI 범위 밖
4. **시간이 지나 어떻게 변했나?** 검증된 성과 3종만 성과그래프. 참고 NAV 관측 그래프는 명확히 `투자성과 아님`, 끊긴 날 연결 금지
5. **다음에 어디를 볼까?** 계좌/성과/전략, 필요 시 Observatory로 1회 이동. 메뉴는 화면 크기당 전역 1세트만

### 데스크톱 1440px
- 상단 1줄: 이름 / 전역 탭 1세트 / 원천 기준시간 / 동기화 상태
- 첫 행 2열: 왼쪽 **NAV + 당일 손익/순입출금**, 오른쪽 **최우선 알림 0~3개**
- 둘째 행 2열: 왼쪽 **관측 NAV 그래프(명확히 참고용)**, 오른쪽 **4계좌 기여 또는 NAV 구조** (상태별 제목/범례 분리)
- 셋째 행: 전략(읽기전용)·시장(Observatory)·성과 상세로 빠른 진입. 트레이딩 CTA 없음.

### 비교할 B안 '분석형 Home'
NAV/차트/계좌별 투자 노출/전략 조건을 첫 화면에 모두 펼치는 방식. 풍부하지만 모바일에서 판단까지 스크롤이 길고 미검증 수치가 많으면 비어 보이므로 권고하지 않음. 상세 탭으로 넘기는 것이 낫다는 가설을 ROY가 반박해도 좋다.

## 4. 반드시 유지할 안전·데이터 계약

- `canonical.snapshot_id`와 `live.snapshot_id`가 모두 존재하고 일치할 때만 해당 집계 표시. 지연·부분불일치면 명시적으로 차단.
- 입금/인출/배당/환전 효과와 투자손익 혼용 금지. `NAV change != investment P&L` (입출금 등 차이).
- 현재 NAV 막대 / 투자손익 막대는 서로 다른 지표, 서로 다른 제목과 단위. 관측 NAV 선 그래프는 투자수익률로 표현하지 않음.
- `CT_RECONCILED_PERFORMANCE_HISTORY_V1`을 검증할 수 없으면 투자성과 3종 그래프를 만들지 않음. 가짜 곡선/평탄선/0원 금지.
- TRI-POD는 별도 계좌가 아니며 Toss 내 전략으로 중복 합산 금지. 전략을 자동매매 신호처럼 장식하지 않음.
- P0 계보·원천·스냅샷 오류는 상단에 한 줄로 반드시 표출하되 세부 재현정보는 펼침 보기.
- `ctui=v1` 복귀 동작 유지. NAV·계좌·성과·전략·품질 기존 경로와 탭 원본 유지. 기존 PB View/Observatory 별개.
- 새 백엔드/유료 서비스/시세 수집 주기 변경/거래 기능/자산·전략 연산변경 없음.

## 5. 시각/접근성 지침
- 모바일 시작 화면 기준 첫 NAV까지 과도한 상단 패널/중복 안내/메뉴가 없어야 함.
- 한 화면에 전역 메뉴 1세트; 모바일 하단 5개, 768px 이상 상단 기존 메뉴. 빠른 경로 버튼의 복제는 금지.
- 숫자는 `tabular-nums`, 1차 강조값 NAV, 2차 손익, 3차 주석. 빨강 상승/파랑 하락은 국내 관례 유지하되 +/−/단위 함께 표기.
- 각 카드 제목은 질문으로 즉시 의미 파악: '지금 자산', '오늘 변동', '확인이 필요한 것', '자산 변화 기록'.
- 필수 접근성: 44px 터치영역, 320~390px 줄바꿈, 안드로이드 브라우저 safe area, 가로 회전, 키보드, screen-reader, 숨겨진 메뉴 focus.
- 데이터 미제공은 한 줄 '원천 준비 중' + 확인 경로; 빈 막대나 3개 텅 빈 그래프 상자를 노출하지 않음.

## 6. ROY에게 독립 반박 요청 (디자인 검토만)
1. 현재 V2 첫 화면을 10초 훑었을 때 사용자의 실제 의사결정에 가장 가치가 낮은 요소 3개와 이유?
2. A안의 NAV→알림→관측 그래프→기여 순서가 과도하게 상태 점검 중심인지? 더 나은 순서와 화면상 지배적인 숫자는?
3. 4계좌 공통 기준일, 투자손익/순입출금, 참고 NAV, 검증된 성과 3종의 의미 혼동·오도 위험은 어디인가?
4. 모바일 390px 상단 접힘/탭 중복/과도한 높이/스크롤 복원/기기 회전의 테스트 누락은?
5. 지금 공개 코드 기준 실현 가능한 P0/P1/P2, 위험과 잠재 회귀, 기존 테스트 및 반드시 추가할 E2E. **실제 인증 화면은 보지 못한 경우 반드시 UNVERIFIED.**
6. A안에 반대한다면 B안 또는 개선 C안을 구체적 대안으로 제시. **기존 PR PASS 반복 금지.**

## 7. 사용자 승인 전 해야 할 일과 승인 후 할 일

**승인 전:** source audit + ROY 독립 의견 + 현재 화면 대비 정보/우선순위 표 + 모바일/데스크톱 시안 + 시행 단계 산출. 이 문서/PR의 존재는 UI 변경 승인 아님.

**승인 후:** 첫 화면 read-only 변경 PR 별도 → 360/390/599/767/820/1363 합성 Playwright·단일 메뉴 검증 → 데이터 4종(VERIFIED/PARTIAL/MISMATCH/STALE) 테스트 → 실제 인증된 본인 기기 확인(사용자 스크린샷 또는 권한 있는 테스트 세션) → 릴리스 승인 후 병합/배포. 운영값과 UI 진실성은 합성 테스트로 갈음하지 않음.
