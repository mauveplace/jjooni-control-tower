# Observatory 상태 판정·갱신 통합

2026-10-27. 기존 freshness-watchdog와 freshness-all-groups가 같은 그리드를 각각 덮어쓰고 독립 타이머로 같은 상태 파일을 조회하던 경로를 정리했다.

- `freshness-core-v1.js`: 헤더·19개 시장군·상세 해석이 같은 현재 시각 판정을 사용한다. 가상자산의 실제 시세 시각, 합의 레짐의 유효기간, 필수 그룹 누락, 상태 파일 자체의 유효시간을 검사한다. 게시 파일의 생성 시각은 원천 시세 시각을 대체하지 않는다.
- `freshness-watchdog-v1.js`: 단일 그리드 렌더·60초 갱신 소유자다. 숨긴 탭에서는 주기 조회를 멈추고, 화면 복귀·상태 패널 열기·다시 읽기에서 재조회한다. 동시 요청은 기존 공용 reader의 Promise를 공유한다. 이전 값이 남은 조회 실패를 정상 조회로 보고하지 않는다.
- `freshness-all-groups-v1.js`: 그룹 인벤토리만 유지한다. 조회·렌더·타이머·MutationObserver를 갖지 않는다.
- 상태 판정 유효시간은 기본 2시간이다. 시간별 수집·실행 지연 여유를 둔 **상태 평가의 한도**이며 일별 종가·월별 경제지표의 보존기한이 아니다. 초과 시 기준일과 원본 판정은 보존하며 현재 판정은 CHECK_REQUIRED/STATUS_STALE로 구분한다. AI 읽기 계약도 동일한 원칙을 적용한다.
- watchdog는 미국 마감 복구 전용이다. 오후에 오전 기록만 존재한다는 사실 자체가 장애는 아니다. 점검 결과는 ‘당시 결과’로 표시한다. 이후 실제 실행으로 작성되는 기록에는 다음 UTC cron 후보 + 3시간 여유의 `next_check_due_kst`를 포함한다. 토요일 UTC는 제외한다. 기록이 실제로 갱신되지 않으면 예정 점검 지연을 표시하며 현재 시세 전체의 실패로 단정하지 않는다. 기존 기록에 미래 실행 증빙을 만들어 넣지 않는다.
- 빌드의 `now` 주입 시각과 게시 생성 시각을 일치시켜 고정 시각 회귀 검사가 실제 시간에 오염되지 않게 한다.

## 확인 범위

고정 시각의 정상/만료/미래 시각/누락 그룹/조회 실패/가상자산/레짐 경계, watchdog 예약 기한을 검사한다. 브라우저 회귀는 390/820/1363px에서 단일 타이머·20개 타일·초기 2개 상태 파일 조회·실패 후 복구와 헤더/그리드 일치를 확인한다. 실행 결과와 운영 배포 확인은 PR에 기록한다.

## 남은 범위

이 변경은 화면의 상태 모델과 갱신 소유자를 통합한 것이다. 모든 생산 파일을 `status.json` 한 개로 대체하거나, 원천 수집·자동복구를 브라우저 조회와 결합한 것은 아니다. 새 승인 합의 레짐 발행은 기존 별도 PR/운영 절차를 따른다. 전 탭 JSON의 완전한 lazy 전환, 긴 화면 전체 정리, 데이터/UI 배포 분리는 남아 있다. 다른 대화에서 진행 중인 금리 수집·원천 시계열 수정과 이 변경을 동일한 완료 항목으로 집계하지 않는다.
