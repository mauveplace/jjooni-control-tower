# Control Tower 로그인·부팅 재점검 및 이전 개선사항 대조

점검일: 2026-10-26 KST. 비교 기준은 `64f489e0e13d1b7e37ebbc1eb54fac4fca9e7fa3`의 코드와 데이터다. 아래의 ‘이번 수정’은 이 문서가 포함된 PR의 변경을 뜻한다. 실제 사용자 기기의 오류 문구·콘솔·인증된 화면 렌더링 시간은 수집하지 않았다. 따라서 재현 가능한 코드 결함과 사용자 단말에서의 발생 원인을 동일시하지 않는다.

## 로그인 도중 오류가 잠깐 보일 수 있는 경로

1. 부팅 조정기가 `SSOT WAIT`와 tooltip을 곧바로 ‘SSOT 읽기/복호화 실패’로 바꾸고 있었다. 첫 계좌 연결의 일시적 통신 실패가 재시도로 회복돼도, 그 전에 실패 화면이 나타날 수 있었다. 로그인 비밀번호 검증과 계좌 피드 연결이 서로 다른 단계인데 같은 오류처럼 보이던 문제다.
2. 로그인 페이지의 전역 `const $`, `const b64`와 복호화된 페이지의 동명 선언이 같은 Window에서 충돌할 수 있었다. 합성 암호화 화면에 동명 선언을 넣어 검사한다. 실제 암호화 원본에 해당 선언이 있는지 확인한 것은 아니다.
3. IndexedDB 연결과 암호화 셸 fetch에 대기 시간 제한이 없었다. 저장소 차단·통신 지연에 따라 진입이 계속 멈출 수 있었다.
4. 문서 교체 후 오류가 나면 이미 사라진 로그인 DOM에 오류를 표시하다 추가 예외가 날 수 있었다. 승인에 성공한 상태와 화면 마운트 실패를 구분해야 한다.
5. 이전 버전의 계산 모듈이 캐시에 남은 상태에서 새 live bridge만 내려오면 신규 품질 API를 찾지 못해 유효한 스냅샷 적용까지 실패할 수 있었다.

## 이번 수정

- 로그인 처리의 도우미와 비밀번호 재시도 상태를 IIFE 안에 격리한다. 승인된 브라우저의 입력 없는 진입과 명시적 승인 해제는 유지한다.
- 기기 저장소 open/blocked 대기를 제한하고, 늦게 열린 연결은 닫는다. 저장소 조회 실패만으로 기존 승인을 삭제하지 않는다.
- 암호화 셸 조회에 20초 제한을 둔다. 통신·화면 구성 오류는 승인 정보 유지와 함께 재시도를 안내한다. 문서 교체 뒤에도 복구 안내를 안전하게 표시한다.
- 계좌 피드의 `CONNECTING / RETRYING / READY / DEGRADED / BLOCKED`를 명시한다. 정상 초기 대기와 일시적 재시도는 실패 화면으로 전환하지 않는다. 30초 이상 지연되면 확인 동작을 제공하며, schema·snapshot·복호화 검증 실패는 즉시 드러낸다. 계좌 원천 검증을 생략하지 않는다.
- 로그인·계좌 연결·UI 로딩의 단계와 오류 코드를 브라우저의 `__JJOONI_ENTRY_DIAGNOSTICS`에 보관한다. 비밀번호·계좌값을 기록하거나 외부로 전송하지 않는다.
- 부팅 준비 판정은 실제 lineage policy와 검증된 SSOT를 확인한다. 가짜 `ACTIVE` 상태를 사용하지 않는다.
- 오래된 계산 API와의 혼합 캐시에서 새 품질 메타데이터가 없으면 `UNKNOWN`으로 남긴다. 계좌값을 0으로 바꾸지 않는다.
- 모바일 부팅 안내의 폭을 부모 영역 기준으로 제한한다.
- 남아 있던 두 Observatory 지연 로딩 JS의 매번 바뀌는 캐시 키도 제거한다. 실시간 JSONP 데이터 요청은 계속 갱신한다.

## 구조 인벤토리 해석

고정된 ‘필수 34개’만으로 실제 부팅 범위를 설명하면 안 된다. 현재 정적 인벤토리는 선언 UI 34개, 필수 UI 32개, 부트스트랩 8개를 구분한다. 이번 감사 도구는 중첩 로더와 lazy master까지 따라가는 **55개 로컬 JS 후보 그래프**도 기록한다. 55개는 모두 첫 진입에 실행·전송됐다는 실측값이 아니다.

## 검증과 한계

- 로컬 Node 256개, Python 209개 통과. 원래 코드로 초기 대기 테스트를 실행하면 실패하고, 수정 코드에서는 통과하는 회귀 검사를 포함한다.
- 합성 암호화 화면의 동명 전역 변수, 승인 복원·해제, 통신 재시도, 마운트 이후 복구, 모바일 연결 대기·실제 차단·회복 뒤 단일 로더를 브라우저 CI에서 확인한다.
- 실계좌 비밀번호 입력·해독, 실제 사용자 단말 콘솔 수집, 첫 렌더 시간 측정은 하지 않았다. 단말에서 다른 문구가 나타난다면 해당 단계의 진단이 추가로 필요하다.
- 원천 금액·매매 규칙·합의 레짐의 유효기간·체결 상태는 변경하지 않는다.
